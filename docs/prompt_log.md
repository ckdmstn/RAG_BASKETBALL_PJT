# 프롬프트 개발 기록

## 프롬프트 1: 검색어 추출 (F2003)

**테스트 입력**: 선수 박정웅 / 질문 "이 선수는 왜 최연소 기록 얘기가 나와?"

### 1차
- 프롬프트 규칙: 검색어 2~4개 / 문서 제목에 있을 법한 짧은 명사 / "이 선수"는 선택한 선수 이름으로 풀기
- 결과: `['박정웅', 'KBL 최연소 선발 출전 기록', '2024-25 시즌', '2024년 12월 4일 DB전 데뷔']`
- 문제: 선수 정보의 경력 문장에서 날짜·경기 결과를 그대로 가져옴(`2024년 12월 4일 DB전 데뷔`),
  너무 막연한 검색어(`2024-25 시즌`) → 위키백과 문서 제목이 될 수 없어 엉뚱한 문서가 걸릴 위험

### 2차
- 변경:
  1. "위키백과에 문서가 있을 법한 대상의 이름만 (선수, 팀, 대학, 리그, 제도, 기록, 용어)" 규칙 추가
  2. "날짜, 경기 결과, 문장은 검색어로 쓰지 않는다" 규칙 추가
  3. 좋은 검색어 / 나쁜 검색어 예시 추가, 출력 형식 예시 추가
- 결과: `['박정웅', 'KBL 최연소 기록', '2024 KBL 신인선수 드래프트', '안양 정관장 레드부스터스']`
- 개선: 날짜·문장형 검색어가 사라지고, 모두 위키 문서 제목이 될 수 있는 이름이 됨

### 배운 점
- LLM은 "하지 말 것"의 나쁜 예시를 보여주면 규칙을 더 잘 따른다
- LLM 출력은 실행마다 달라서 같은 질문을 여러 번 돌려 안정성을 확인해야 한다

### 구현에서 겪은 문제
- 프롬프트의 `{player_text}`, `{question}` 빈칸이 채워지지 않은 채 전달될 수 있음 → `.format()`으로 채워서 하나의 메시지로 전달
- LLM이 JSON을 ```json 코드블록으로 감싸거나 앞뒤에 설명을 붙일 수 있음 → `parse_json_list`로 배열만 꺼내고, 깨지면 빈 목록으로 안전하게 처리
- LLM이 선수 이름을 빼먹을 수 있음 → 선택한 선수 이름은 코드가 항상 맨 앞에 추가 (F2003)

### 최종 프롬프트
QUERY_PROMPT = """
당신은 KBL(한국프로농구) 전문 사서입니다. 아래 [선택한 선수] 정보와 [질문]을 보고, 한국어 위키백과에서 찾을 '검색어'를 뽑아 주세요.

[선택한 선수]
{player_text}

[질문]
{question}

[규칙]
- 검색어는 2~4개만 뽑습니다.
- 검색어는 위키백과에 문서가 있을 법한 대상의 이름만 뽑습니다. (선수, 팀, 대학, 리그, 제도, 기록, 용어)
- 날짜, 경기 결과, 문장은 검색어로 쓰지 않습니다.
- 질문의 "이 선수"는 선택한 선수의 이름으로 풀어서 생각합니다.

[예시]
- 좋은 검색어: "KBL 최연소 기록", "안양 정관장 레드부스터스", "KBL 신인선수 드래프트"
- 나쁜 검색어: "2024년 12월 4일 DB전 데뷔", "2024-25 시즌", "이 선수가 최연소 기록을 세운 이유"

[출력] 
- JSON 문자열 배열만 출력합니다. 설명 문장은 쓰지 않습니다.
- 예: ["연세대학교 농구부", "고양 소노 스카이거너스"]
"""
