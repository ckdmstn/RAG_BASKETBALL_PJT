# RAG 사용 전후 답변 비교 (F2015)

- 작성일: 2026-10-22
- 방법: 같은 질문을 (가) RAG 없이 LLM에게 그대로 묻고, (나) RAG 파이프라인(수집 → 색인 → 검색 → 근거를 붙인 답변)으로 답하게 해 비교했다.
- 정답 기준: 이 프로젝트가 색인한 데이터(선수 JSON, 팀 정보 JSON, 위키백과). 실제 사실과 다를 수 있는 값도 이 기준으로 판정했다.
- 판정 방식: 답변에 정답 표현이 들어 있는지(키워드)로 자동 판정했다. 근거 제시는 답변의 [근거 n] 표기 여부, 모르는 것을 모른다고 답하는지는 '확인되지 않는다' 등의 표현 여부로 판정했다.

## 정리

### 사실 정확성
- RAG 없이는 정답이 있는 5개 질문을 한 번도 맞히지 못했다. 질문 1~4는 모른다고 답했고, 질문 5(홈구장)는 틀린 사실을 단정했다.
  - 질문 5: LLM은 "안양실내체육관"이라고 답했지만 색인한 자료(팀 정보)에는 "안양 정관장 아레나"로 적혀 있다. 학습 당시의 옛 정보를 그대로 말한 것으로 보이며, 자료 기준으로는 오답이다.
  - 질문 3(자니 오브라이언트 소속팀)은 2026년에 소노로 옮겼다는 최신 정보라 학습 데이터에 없어 모른다고 답했다.
- RAG를 사용하면 5개 질문이 모두 정답이었다. 선수 정보(질문 1, 3, 4), 팀 정보와 위키 문서(질문 2, 5)에서 찾은 근거로 답했다.

### 근거 제시
- RAG 없이는 출처를 댈 수 없고(0/5), 답을 믿을 근거도 알 수 없다.
- RAG 사용 시 5개 답변 모두 [근거 n]이 붙었고, 화면에서 인용한 근거의 종류(선수 정보 / 팀 정보 / 문서), 제목, 원문 링크, 본문 일부를 확인할 수 있다. 질문 2는 팀 정보와 위키 문서 두 근거가 같은 답(3회)을 뒷받침했다.

### 모르는 것을 모른다고 답하는지
- 근거에 없는 질문(질문 6: 혈액형)에서는 두 방식 모두 지어내지 않고 모른다고 답했다.
- RAG 사용 답변은 "문서에서 확인되지 않습니다"로, 어떤 자료를 봤는데 없었는지가 분명하다. RAG 없이 답은 "확인할 수 없다"는 말뿐이라 자료가 없어서인지 모르는 것인지 구분되지 않는다.

### 한계
- 질문이 6개뿐이고, 정답 여부는 키워드 포함 여부로 자동 판정했다(질문 1, 2의 판정은 직접 확인해 보정했다).
- 정답은 이 프로젝트가 색인한 자료 기준이라 실제 사실과 다를 수 있다.
- RAG 없이 질문한 프롬프트에도 "확실하지 않으면 모른다고 답하세요"를 넣었다. 그래서 RAG 없이도 틀린 사실을 지어내는 일이 적었고(1/5), 지시가 없으면 더 많이 지어낼 수 있다.
- LLM 답변은 실행마다 조금씩 달라질 수 있다.

### 결론
이번 비교에서 RAG의 가장 큰 효과는 두 가지였다. 첫째, 최신 정보와 프로젝트 고유 정보(소속팀, 출신 대학, 드래프트)에 정답을 내놓는다. 둘째, 모든 답에 출처가 붙어 사용자가 확인할 수 있다. 반면 LLM만으로는 대부분 모른다고 답했고, 아는 것처럼 답한 홈구장은 옛 정보였다.
